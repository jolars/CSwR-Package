# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

## What this is

`CSwR` is an R package, a companion to the book *Computational Statistics with R* (cswr.nrhstat.org). It ships five datasets and a small set of utilities (`tracer`, `terminator`, `rng_stream`, `force_all`, `plotter`) used throughout the book.

## Common commands

Tasks are wrapped with [`go-task`](https://taskfile.dev) (`task <name>`); each maps to an underlying R / `R CMD` invocation listed in `Taskfile.yml`:

- `task install` — `R CMD INSTALL .` (default task)
- `task test` — `devtools::test()`
- `task check` — `devtools::check()` (full R CMD check)
- `task docs` — regenerate `man/` and `NAMESPACE` via `devtools::document()`
- `task build` / `task build-cran` — produce a tarball one level up
- `task readme` — render `README.qmd` → `README.md` with Quarto

Run a single test file: `Rscript -e 'devtools::test_active_file("tests/testthat/test-tracer.R")'`.
Run a single test by name: `Rscript -e 'devtools::test(filter = "tracer")'` (matches the file suffix after `test-`).

R code is formatted with [air](https://posit-dev.github.io/air/) (config in `air.toml`: 80 cols, 2-space indent). A pre-commit hook runs `air format --check` — run `air format .` before committing.

## Dev environment

The repo uses `devenv` (Nix) — `devenv.nix` declares R + the packages used during development (`devtools`, `roxygen2`, `testthat`, `ggplot2`, `rlang`, `bench`, `covr`, `quarto`, ...) plus `go-task`, `air`, and `quartoMinimal`. With direnv allowed (`.envrc` present), entering the directory provides the toolchain.

## Architecture

The package surface is small and lives entirely in `R/`:

- `tracer.R` and `terminator.R` implement closure-based callback objects. Both follow the same pattern: the constructor captures local state (`env`, counters, saved values) in a closure, returns an S3-classed list of functions (`tracer`/`terminator` plus `clear`, and for tracer also `get`), and the returned `$tracer` / `$terminator` function is intended to be passed as a callback into an iterative function. Inside the callback, `parent.frame()` is used to reach into the caller's environment so traced expressions can read its variables without being co-mingled with them. Tracer also supports a `Delta` print cadence, a `save` toggle, optional timing via `bench::hires_time()` (adjusted by `gc.time()` to discount GC), and a `plotter` expression for live plots.
- `plotter()` returns a quoted expression (built with `bquote()`) that both tracer and terminator can evaluate inside their callback env to update a plot window opened by the shared internal helper `new_plotter_window()` (defined in `tracer.R`, used by both).
- `rng_stream.R` is a closure over a cache vector; refill size scales by an adaptive `fact` factor when the requested-per-call rate `r` is smaller than the current cache `m`.
- `force.R` provides `force_all()`, which forces evaluation of every formal argument in `parent.frame()` plus anything passed through `...`. Closures that capture variables should call this before returning the inner function to avoid lazy-evaluation surprises (see the example in the roxygen).
- `data.R` is documentation-only (`"name"` strings) for the five `.rda` files in `data/`. The originating scripts and raw sources live in `data-raw/` (excluded from the build by `.Rbuildignore`).

S3 methods exported by the package (see `NAMESPACE`): `[.tracer`, `print.tracer`, `summary.tracer`, `autoplot.tracer`, `autoplot.trace`, `print.terminator`. `summary.tracer` returns a `trace`/`data.frame` with a cumulative `.time` column; `autoplot.trace` plots a traced quantity against time with a log y-axis by default.

## Conventions

- Roxygen2 with markdown (`Roxygen: list(markdown = TRUE)` in DESCRIPTION). After editing roxygen blocks run `task docs` so `man/` and `NAMESPACE` stay in sync — both are generated.
- Exports go through `@export` tags; do not edit `NAMESPACE` by hand.
- Bump `Version:` in `DESCRIPTION` and add a `NEWS.md` entry for user-visible changes.
- Datasets are regenerated by running the matching script in `data-raw/` (e.g. `data-raw/nuuk.R`); don't edit the `.rda` files in `data/` directly.
